How to use this page. You only retake the skills you haven't passed. Check the list under your badge on STACK and go straight to those sections. The quiz above tells you where to look too: each wrong answer links to the section that covers it.

Each section has three kinds of task:

  • Explain it. Answer out loud or in writing, without notes. The assignment asks you to explain code, so this is the most important practice.
  • Predict it. Write down the exact output before revealing the answer. If you got it wrong, work out why.
  • Code it. Short programs with test cases so you can check your own work. Tick them off as you go; this page remembers.

When you explain code, say what it does, why, and what type each value is. Compare:

  • Weak: “it adds them.”
  • Strong: “it joins the two strings, because + on two str values is concatenation, so the result is the str "103".”

01Strings and numbers

Every value in Python has a type, and the type decides what operators do. + adds two ints but joins two strs. Mixing them is an error, because Python won't guess which one you meant.

Explain it

  1. What is the difference between /, // and %? Give an example of when you'd use each.
  2. Why does "5" + 2 cause an error, while "5" * 2 does not? What does "5" * 2 produce?
  3. What type does input() always return? What must you do before doing arithmetic with it?
  4. Strings are immutable. What does that mean? What does s.upper() do to s?
  5. What is the difference between 10 + 3, "10" + "3" and str(10) + str(3)?

Predict it

s = "Edinburgh"
print(s[0], s[-1], s[2:5], len(s), s.upper().count("I"))
E h inb 9 1. Index 0 is the first character and -1 the last. [2:5] gives indices 2, 3 and 4, because the end is excluded. "EDINBURGH" contains one I.
print(7 // 2, 7 % 2, -7 // 2, 2 ** 3, 7 / 2)
print(int("7") + 2, str(7) + "2")
3 1 -4 8 3.5 then 9 72. // rounds down, so −3.5 becomes −4, not −3. / always gives a float. str(7) + "2" joins two strings.

02Conditions and logic

A condition is just an expression that evaluates to True or False. An if/elif/else chain checks conditions top to bottom and runs the first branch that matches. Everything after it is skipped.

Explain it

  1. Explain and, or and not with an everyday example (“you can enter if you have a ticket and ID”).
  2. What is the difference between = and ==?
  3. Why does order matter in an if/elif/else chain? Give an example where swapping two branches changes the output.
  4. A student writes if n > 1 or n < 10: to check n is between 1 and 10. Why is it wrong? Give a value of n that proves it.

Predict it

x = 0
print(x == 0 or 1/x > 2)                 # does it crash?
print(not (True and False) or False)
print(bool(""), bool("0"), bool(0), bool([]))
True, True, False True False False. No crash: x == 0 is already True, so or stops there and never runs 1/x (“short-circuiting”). Empty things and zero are falsy, but "0" is a non-empty string, so it is True.

03Repetition and loops

Use a for loop when you know what you're looping over: a list, a string, a range. Use a while loop when you loop until something happens and don't know in advance how many times that will be.

Explain it

  1. When would you use a for loop instead of a while loop?
  2. What values does range(2, 11, 3) produce? What about range(5)?
  3. What is the difference between break and continue?
  4. What is an infinite loop? Write a while loop that never stops, then fix it.
  5. Draw a trace table for the even-sum program on the practice sheet (1.2), then for the while loop below.

Predict it

for i in range(1, 10, 3):
    print(i, end=" ")
1 4 7. It starts at 1, steps by 3, and stops before 10.
n = 10
c = 0
while n > 1:
    n = n // 2
    c += 1
print(n, c)
1 3. n goes 10 → 5 → 2 → 1, which is three halvings. Then 1 > 1 is false, so the loop stops.

04Lists, sets and dictionaries

Choose by how you'll look things up:

  • A list keeps order and is looked up by position (marks[1]).
  • A dictionary is looked up by key (marks["Alice"]).
  • A set answers one question fast: “is this in here?”. It has no order and no duplicates.

Explain it

  1. When would you choose a list, a set, or a dictionary? Give an example of each.
  2. Why does my_set[0] fail? Why does adding the same value to a set twice not create two copies?
  3. What does it mean that lists, sets and dictionaries are mutable?
  4. After b = a, why does changing b also change a? How do you make an independent copy?
  5. In for k in d:, where d is a dictionary, what values does k take? How do you get each value too?

Predict it

a = [1, 2, 3]
b = a
b.append(4)
print(a, len(a))
[1, 2, 3, 4] 4. b = a doesn't copy the list. It gives the same list a second name. Use a.copy() for a real copy.
d = {"x": 1}
d["y"] = 2
d["x"] += 5
print(d, len({1, 2, 2, 3, 3, 3}))
{'x': 6, 'y': 2} 3. Assigning to a new key adds it. A set keeps each value once, so it's {1, 2, 3}.
On the practice sheet (7.3), so expect it: aliasing. saved = seen then saved.add(10) changes seen too, because both names point at one set.

05Functions

A function packages up some steps behind a name. Data goes in through parameters and comes out through return. Variables created inside a function are local: they exist only while that call is running.

Explain it

  1. What is the difference between a parameter and an argument?
  2. What is the difference between return and print? What does a function without return give back?
  3. What is a default parameter value? What are keyword arguments, and why can they be given in any order?
  4. What is local scope? Why can't you use a variable from inside a function after the call finishes?
  5. Give two reasons why splitting a program into functions beats one long block.

Predict it

def f(x, y=2):
    return x * y
print(f(3), f(3, 4), f(y=1, x=5))
6 12 5. The default y=2 is used only when y isn't given. Keyword arguments are matched by name, so their order doesn't matter.
def g(n):
    n = n + 1

total = 5
g(total)
print(total)
5. Inside g, n is a local name. Rebinding it doesn't touch total, and g doesn't return anything.
def h():
    print("hi")

r = h()
print(r)
hi then None. h prints but returns nothing, so r is None. This is the classic print-vs-return mistake.

06Classes and instances

A class describes a kind of thing: what data it holds and what it can do. Each object made from it is an instance with its own copy of the data. self is how a method refers to “this particular object”.

Explain it

  1. What is the difference between a class and an instance? Use your own analogy, not “blueprint and house”.
  2. What is self? Why does every method take it as its first parameter?
  3. When is __init__ called? When is __str__ called?
  4. What is the difference between an instance attribute and a class attribute? If you change one, which objects see the change?

Predict it

class Counter:
    def __init__(self):
        self.count = 0

    def click(self):
        self.count += 1
        return self.count

c1 = Counter()
c2 = Counter()
c1.click(); c1.click(); c2.click()
print(c1.count, c2.count)
2 1. Each object has its own count, set to 0 by __init__ when that object was created.

07Introduction to generative AI

A language model writes code by predicting what text is likely to come next. It doesn't run the code or check that it's correct. That's why it can be confidently wrong, and why your understanding is what gets assessed.

Explain it

  2. Name three things you'd check before trusting code an AI wrote for you.
  3. The assessment asks you to explain code without notes. Why doesn't copying AI answers into your report prepare you for that?
  4. What's a good way to use AI while revising? What's a bad way?

08Testing and documentation

A docstring says what a function is supposed to do. A test checks that it actually does. “I ran it once and it worked” is not a test. A test is something you can rerun every time you change the code.

Explain it

  1. What is a docstring? Who reads it? How is it different from a comment, and from a return value?
  2. What does assert do? What happens when an assertion fails?
  3. What is an edge case? Give two for a function that finds the largest number in a list.
  4. Why is “I ran it once and it worked” not a test?

Predict it

def double(x):
    """Return x multiplied by two."""
    return x + x

assert double(3) == 6
assert double("ab") == "abab"
assert double(0.1) == 0.2
assert double([1]) == [2]      # which line fails, if any?
Only the last fails, with an AssertionError. double([1]) is [1, 1], because + on lists joins them rather than adding the numbers inside. The float one happens to pass, but floats aren't always exact: try 0.1 + 0.2 == 0.3. The docstring says “multiplied by two”, but the code does different things for different types. Tests are how you find that out.

Code it

coreTake three functions you wrote in Section 5. Give each a docstring and at least four assert tests, including one edge case.

coreThis should return the largest number in a list. Write a test that exposes the bug, then fix it.

def largest(nums):
    best = 0
    for n in nums:
        if n > best:
            best = n
    return best
